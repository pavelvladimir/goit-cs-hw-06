# Тести та результати

Стан на 05.11.2026. Локальні перевірки виконувалися на macOS ARM64,
контейнери — Linux ARM64. Python на хості 3.13.2, у runtime — 3.13.5.

## Як запустити

```bash
make sync
make install-browsers
make check
```

`make check` запускає lint, перевірку типів і API-контракту, збірку frontend,
Python-тести, Playwright та Docker-тести. Поріг coverage — 90%.
Для перевірок без Docker і браузерів є `make check-unit`.
Звичайний `pytest` не запускає Docker без прапорця `--integration`.

Інтеграційні тести мають власні паролі, випадковий порт і тимчасовий volume.
Вони перевіряють запис у MongoDB, збої БД, збереження даних після recreation,
завершення процесів, резервні копії, обмеження доступу й приватність логів.
Браузерні тести охоплюють клавіатуру, axe, вигляд сторінок та надсилання форми
з JavaScript і без нього.

## Останні локальні перевірки

| Перевірка | Результат |
| --- | --- |
| Python | 371 тест пройдено |
| Coverage | 99,03% загалом |
| Клієнт API | 16 тестів пройдено |
| Chromium, Firefox, WebKit | 120 тестів пройдено |
| Docker та MongoDB | 22 тести пройдено |

Повний `make check` пройшов після оновлення minimatch і Distroless. Після
додавання ще двох перевірок SHA-256 build-скриптів повторено всі Python-тести.

Нові тести перевіряють взаємне виключення backup/restore у різних процесах,
утримання блокування під час cleanup і restart, звільнення після помилки та сигналів.
Окремо перевірено випадок втрати підтвердження: HTTP повертає 503, а один запис уже є в БД.

## Навантаження

Результат трьох фаз POST по 10 секунд від 01.11.2026:

| Паралельність | Записів/с із підтвердженням | HTTP 503 | p95 успішних запитів |
| --- | --- | --- | --- |
| 1 | 18,9 | 0 | 8,6 ms |
| 8 | 146,9 | 0 | 8,3 ms |
| 16 | 253,7 | 138 | 9,0 ms |

Разом із контрольним POST після навантаження підтверджено 4400 записів.
Усі вони знайдені в MongoDB без дублікатів. Максимальна затримка сягала 1,07 с,
пік вибірок RAM app — 111,2 MiB. Генератор обмежував частоту запитів, тому ці числа
не означають максимальну пропускну здатність. [Методика](resilience.md#навантаження).

## Linux, CI та аудит

`make check-linux` запускає локальні тести й три браузери в окремому Linux-контейнері.
Повний Linux-прогін проходив до змін request ID та POST benchmark;
після блокування backup/restore окремо пройдено 57 відповідних тестів.

[GitHub Actions](https://github.com/pavelvladimir/goit-cs-hw-06/actions/workflows/check.yml)
запускає повний `make check` на Linux AMD64. Тимчасово використовується Ubuntu 22.04:
після оновлення ядра runner Ubuntu 24.04 MongoDB 8.0.32 завершується ще до запуску тестів.
Повернення на 24.04 — після виходу Percona-образу з виправленням
[SERVER-131779](https://jira.mongodb.org/browse/SERVER-131779).
Версії ядра й Docker видно в логах; у разі помилки туди потрапляють і логи контейнерів.
Windows і тривалі навантаження не перевірялися.

05.11.2026 Python audit і повний npm audit пройшли без знахідок.
Для [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249)
додано override minimatch 10 → 11.0.1. `make audit-all` також пройшов;
образ має 42 точні винятки до 05.12.2026 для недоступних у нашому застосунку шляхів.
Це не означає, що всі системні бібліотеки вже виправлені.
`make audit` перевіряє Python. Системні пакети кінцевого Distroless-образу та його
SBOM тепер перевіряє окремий `make audit-image`. [Команди й результат](image-audit.md).
`make audit-all` об'єднує його з Python/frontend SBOM та наявними аудитами залежностей.
[Результати й порівняння SBOM](dependency-audit.md).
